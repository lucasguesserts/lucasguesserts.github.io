Project: 3D-SCLP Paper

After finishing my Master Thesis, my professors invited me to write a scientific paper based on our finding. Here, I documented my journey.

The Role of Writing in Science

My professor friend told me that in his academic world, 'publish or perish' is really true. He does not care if nobody reads it or understands it as long as it is published.

Scientific writing is about advacing our knowledge, and that requires effective communication.

Learning How to Write an Scientific Article

I do not know how to write scientific papers so I looked for resources on it. I considered two courses and picked the first one because it seems to have more information and has better reviews:

  • ✅ Coursera Course: Writing in the Sciences - Stanford University
  • ❌ Coursera Course: How to Write and Publish a Scientific Paper (Project-Centered Course)

How to Declutter

  1. understand the idea and how it is expressed
  2. remove clutters until none is left:
    1. dead/empty words and phrasees
    2. long words and phrases that can be short
    3. repetitive words and phrases
    4. unnecessary jargon and acronym
    5. needless adverbs and prepositions
    6. negatives (transform into positives)
    7. there is/there are

Open-Science Data Repositories

My goal is to make the research data comply with the FAIR principles: Findable, Accessible, Interoperable, Reusable.

My requirements for data repositories:

  1. allow different licenses;
  2. be easy to use (good UX), with the license clearly stated;
  3. be built entirely with open-source code, with ongoing development;
  4. be backed by a large support team (in case of issues, data breaches, etc);
  5. allow for upload of any type of data;
  6. sync with GitHub (somehow...);
  7. commit to long-term storage;
  8. be owned by a public organization with a good record, and funded with public resources (important because of conflict of interest);
  9. be well-known;
  10. be a data storage (store the data in it, instead of using other tools such as google drive, dropbox, github);
  11. be free (no fee required);
  12. have robust metadata standards;
  13. support versioning (I might want to add bug fixes or missing data);
  14. to have in the page easy access to citing;
  15. be interoperable: if I search for a content that is available in another database, it must find it (for instance, if I search for something that is in unicamp's repository using harvard's repository, I should be able to find it) - none of them provide this;
  16. be distributed (instead of centralized) - science belongs to everyone and there must not be one party that controls all the information;

There is no repository that satisfy all requirements. Nevertheless, balancing them, I chose to use Zenodo and REDU (the references have a list of repositories and comparisons of them).
